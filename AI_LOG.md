# Работа с ИИ

## Инструменты

- **Codex** (desktop-приложение), модель GPT-6.1 Sol: первоначальная реализация,
  обсуждение кода, ревью моих изменений, подготовка тестов.

Контекст для Codex: исходное задание в `TZ.md`, правила и архитектура в `AGENTS.md`,
примеры из моего предыдущего FastAPI-проекта.

## Ключевые запросы

1. «Прочитай TZ.md и AGENTS.md. Код пока не пиши. Предложи структуру проекта,
   схему БД, список эндпоинтов и места, где легко ошибиться в деньгах,
   идемпотентности и статусах.» Сначала план, и только потом код.
2. «Я переписал database, dependencies, env.py и добавил папку app. Посмотри
   текущее состояние, ничего не трогай.» Попросил проверить мои ручные изменения,
   не давая агенту править файлы.
3. «Добавь тестирование.» В контексте перечислил сценарии: промокод с регистром,
   график 3/6/12 месяцев, повтор Idempotency-Key, запрещённый переход, 404 
   и потребовал проверять результат (суммы, статус в БД, число платежей), а не только код ответа.

## Где модель ошиблась или предложила слабое решение

- **Не читался `.env`.** Приложение не подтягивало `DATABASE_URL` из файла.
  Заметил при запуске. Исправил `env.py`.
- **Роутеры возвращали ORM-модели.** Аннотации возвращаемых значений в файле
  роутов были моделями БД, а не схемами из `schemas`. Заметил при чтении роутера.
  Перешёл на явное преобразование через `model_validate` и записал правило
  в `AGENTS.md`.
- **Слишком широкая обработка `IntegrityError`.** Любая ошибка целостности
  превращалась в «дубликат ключа». Заметил при разборе кода. Теперь
  `DuplicateIdempotencyKeyError` бросается только при подтверждённом конфликте
  ненулевого ключа, остальные ошибки пробрасываются после rollback.
- **Лишнее дробление.** Небольшие расчёты были разнесены по трём файлам.
  Оставил один `services/billing.py` с отдельными чистыми функциями.

## Проверка

- Вручную в Swagger: повтор с одним `Idempotency-Key` возвращает тот же платёж
  (сначала 201, затем 200); без ключа создаются новые платежи. Успешная смена
  статуса работает; запрещённый переход даёт 409 `invalid_transition`, статус
  не меняется.
- Локально прогнал `pytest`, `black`, `isort`, `mypy`:
  58 тестов прошли усппешно, линтеры также без замечаний.
- Docker: проверил `docker compose up --build` из чистого клона,
  платёж сохранился после перезапуска
